# WS 模拟器 · Pygame v15

在 New_version 目录运行 `python main.py`。依赖 Python 3.11、Pygame、Tkinter（仅用于 Replay 文件选择）。若缺少 Pygame，执行 `python -m pip install -r requirements.txt`。

## 界面与操作

原始视觉稿 `ui/pygame/pygame_stage_grid_mock_v15.py` 保持原样，新适配器 `ui/pygame/app.py` 复用它的中央几何布局。P2 在上、P1 在下：P2 后列—P2 前列—P1 前列—P1 后列；对应位置对齐。沿用 150 像素正方形网格、15 像素间距、107×150 纵向卡框，整体随窗口缩放；网格边缘不绘制。

最右列集中放置所有操作确认、种子输入、Replay、区域顺序和最近记录。左列保留空白。

- 点击种子框，Ctrl+A 清空后输入整数，点击按种子开局；也可随机新局。
- 中央手牌可选择，右侧确认换牌。先手、后手依次操作，允许选择 0 张。
- 换牌结束进入先手第 1 回合。右侧按钮推进重置、抽卡、计时、主要、高潮、攻击、结束阶段；结束后轮到另一玩家。
- 进入抽卡阶段从卡组顶部抽 1 张。
- 计时阶段选择一张己方手牌，在右侧执行计时：手牌移至计时顶部，从卡组顶部抽 2 张。每回合一次，也可跳过；完成后仍需手动推进。
- 主要阶段选择一张己方手牌，再点击己方前列或后列目标，最后在右侧确认出牌。对已占用位置出牌，会先将旧卡移至控制室，再产生新卡登场事件。
- 点击双方卡组、控制室或计时区，右侧分页查看完整区域顺序。检查器随操作更新。
- 手牌单行最多显示 7 张，通过各自左右箭头浏览。双方手牌与计时均保持屏幕左侧为底部，右侧朝顶部。
- Esc 清除手牌及舞台目标选择。保存和载入 Replay 通过系统文件选择窗口完成。
- 库存、思出、高潮、等级区沿用新稿占位，暂未实现相应规则。

## 数据与规则约定

双方各 50 张测试角色：0 级、0 费、力量 500、灵魂 1、黄色、无特征、无触发，卡名“测试”、卡牌编号 T-001。实例序号 1–50、带 P1/P2 的唯一实例 ID 与卡牌编号不同。CardDefinition 保存种类及基础属性，预留编辑器数据接口。

所有区域的数据索引 0（位置 #1）始终为顶部，最后一位为底部。手牌与计时仅在显示时反向排列；计时显示底部六张、容量 50 张。卡组从顶部抽牌，新抽牌追加到手牌数据底部。控制室按顶部插入弃牌。

UI 只持有独立快照。所有比赛操作仍经 `Application.dispatch(Action)`，由 engine.py 验证和结算。rule_resolution.py 在登场事件之前处理舞台重叠。原 Tkinter 界面保留在 ui/app.py，默认入口已改为 Pygame。

尚未实现非零费用支付、升级、卡组刷新、能力效果、攻击结算和胜负。空卡组抽牌、计时区已满或卡组不足两张的计时操作会被拒绝，状态不变。

Replay 版本 4 记录种子、配置、换牌、阶段、计时和出牌 Action 以及逐步状态哈希。支持读取版本 1–3。固定测试卡定义由引擎配置生成；未来开放编辑需增加定义快照。跨 Python 随机实现不保证兼容，状态校验不一致会拒绝载入。

## 手动验收

按用户要求，本次迁移未运行自动测试，也未启动界面。

1. 同种子重复开局，核对先后手与双方手牌一致。
2. 双方依次换牌（包括 0 张），检查卡组数量和控制室顺序。
3. 进入抽卡阶段检查抽 1 张；计时操作检查计时增加 1 张、手牌净增 1 张。
4. 主要阶段分别向己方前后列出牌，再覆盖已有角色，检查旧卡进入控制室；对方位置不能作为目标。
5. 手牌超过 7 张时浏览左右箭头；检查双方卡组、控制室分页及顶部/底部编号。
6. 保存 Replay 后随机开局，再载入确认状态恢复；推进至结束阶段确认玩家切换。
7. 调整窗口大小，检查场地缩放和点击区域一致。

所有开发文件位于 New_version；Old_version 仅供参考。
